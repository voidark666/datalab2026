### logtwo

白名单只有 `> < >> << |`，参考实现用的 `if`、`&` 和数组都不能用。思路分三点：

1. 目标是最高位 1 的下标 `p ∈ [0, 31]`，它用二进制表示就是 5 位，所以 **5 次比较**足以二分确定；
2. 每轮维护不变量"进入步长 `2^k` 这一轮时 `v < 2^(2k)`"。在这个前提下，"第 k~2k−1 位里有 1"**等价于** `v ≥ 2^k`，于是参考实现里的位掩码退化成一次普通比较（阈值取 `2^k − 1`，因为白名单没有 `>=`）；
3. 用"无分支三件套"消掉 `if`：比较结果本身就是 0/1，可以当开关；`<< k` 把它变成增量 `2^k`；`|` 负责累加（16/8/4/2/1 的二进制位互不重叠，`|` 与 `+` 等价，而白名单里没有 `+`）。剥离动作用 `v >>= s` 完成，`s = 0` 时就是空操作。

```
for k in {16, 8, 4, 2, 1}:
    s = (v > 2^k - 1) << k      # 条件成立 → 剥离 2^k 位
    r = r | s
    v = v >> s
return r
```

结果 `r` 的五个二进制位，就是五次比较的答案从高位到低位拼出来的。

### leftBitCount

不许 `if`/`while`，全部用位运算。核心恒等式：**前导 1 的个数 = 32 −（`~x` 中最高位 1 的位置 + 1）**。

1. 令 `y = ~x`：`x` 的前导 1 变成 `y` 的前导 0；
2. 涂抹：`y |= y >> 1/2/4/8/16` 把最高位 1 以下全部变成 1，此时 `popcount(y)` 恰好是"最高位位置 + 1"（移位量 1+2+4+8+16 = 31，刚好覆盖整个字）；
3. SWAR popcount：用 `0x55555555 / 0x33333333 / 0x0F0F0F0F` 把相邻 1/2/4 位两两归并相加；最后 `y + (y >> 8)`、`y + (y >> 16)` 累加各字节的计数，因为每字节计数 ≤ 8，加法不会跨字节进位，所以这两步不需要掩码；
4. 白名单没有减号，答案写成 `33 + ~y`（即 `32 − popcount`）。

边界情况不需要特判：`x = 0` → `y = -1` → popcount 32 → 答案 0；`x = -1` → `y = 0` → popcount 0 → 答案 32。

### float_i2f

分四步：

1. `x == 0` 直接返回 0；
2. 符号位单独拆出，绝对值用**无符号补码** `~ux + 1` 求。若用有符号取负，`INT_MIN` 会溢出（未定义行为），而无符号补码能得到正确的 `2^31`；
3. `while (!(ux >> e)) e--` 从 31 往下找到最高位 1 的位置 `e`，于是阶码字段为 `e + 127`；
4. 规格化与舍入，是本函数的主体：
   - `e ≤ 23` 时有效位数不超过 24 位，**一定可以精确表示**，左移对齐即可，无需舍入；
   - `e > 23` 时低 `shift = e − 23` 位必须丢弃，按 IEEE 默认的**就近偶数舍入**处理：把丢弃部分 `low` 与半值 `half` 比较，大于则进位、小于则舍去、**恰好相等（平局）时进位与否取决于保留部分末位 `sig & 1`**，从而把结果凑成偶数；
   - 舍入可能使有效数进位到 25 位（`sig >> 24`），此时右移一位并把 `e` 加一。典型例子是 `0x7FFFFFFF`：舍入后变成 `2^31`，位模式为 `0x4F000000`。

符号数刚好 30：因为 `&&`、`||`、`?:` 都不在白名单里，"大于"和"平局"这两个条件没法写成一行表达式，只能先用两个 `if` 分别设置 `roundup`，再统一相加，这是最省符号的写法。

## 反馈/收获/感悟/总结

这次实验最大的收获是"把控制流翻译成位运算"的思路：比较结果可以直接当 0/1 使用，左移可以代替分支，按位或可以代替累加。印象最深的两处是 `float_i2f` 的舍入——必须与 `(float)x` 的就近偶数舍入完全一致——以及 `leftBitCount` 的涂抹 + SWAR popcount。真正的难点不只在算法，还在于**符号数上限**：为了省一个符号，有时必须把两个条件合并成一个 `roundup` 变量，或者把减法写成 `33 + ~y`。此外，先读 `test.py` 的源码把合规口径弄清楚（哪些算符号、哪些只在白名单里查）比反复试错有效得多。
